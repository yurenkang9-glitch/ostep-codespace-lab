# OSTEP Ch.7 Homework Answers — CPU Scheduling

本作业使用 `./ext/ostep-homework/cpu-sched/scheduler.py`，比较 FIFO、SJF、RR 三种调度器。所有作业都在时间 0 到达，时间单位与模拟器输出一致（秒）。

指标定义：

- 响应时间 Response = 首次运行时刻 − 到达时刻
- 周转时间 Turnaround = 完成时刻 − 到达时刻
- 等待时间 Wait = 处于就绪状态、但没有运行的总时间。本作业中等于“周转时间 − 作业长度”

做法：每题先不加 `-c` 运行，只看作业列表并手算（Prediction）；再加 `-c` 运行核对（Verified）。全部 `-c` 输出保存在 `data/`，可用 `bash hw/chapter7/run_all.sh` 重新生成。33 组输出与预测逐项一致。

## Q1

> Compute the response time and turnaround time when running three jobs of length 200 with the SJF and FIFO schedulers.

- Prediction / 预测:

预测命令：`scheduler.py -l 200,200,200 -p FIFO` 与 `-p SJF`。

| 作业 | 长度 | 响应 | 周转 | 等待 |
|---|---|---|---|---|
| Job 0 | 200 | 0 | 200 | 0 |
| Job 1 | 200 | 200 | 400 | 200 |
| Job 2 | 200 | 400 | 600 | 400 |
| **平均** | | **200.00** | **400.00** | **200.00** |

FIFO 与 SJF 结果相同。

- Reasoning / 理由:

三个作业一样长。SJF 按长度排序时遇到相同长度会保持原顺序（模拟器用的是稳定排序），所以运行顺序和 FIFO 一样，都是 0 → 1 → 2。每个作业要等前面的作业全部跑完才能开始，所以响应时间依次是 0、200、400。非抢占调度下，作业开始后会一直运行到结束，因此等待时间等于响应时间。

- Verified result / 验证结果:

完整输出见 `data/q1_fifo.txt`、`data/q1_sjf.txt`。两者的平均响应时间都是 200.00，平均周转时间都是 400.00，与预测完全一致。

- Analysis / 分析:

作业等长时，SJF 无法通过“把短作业提前”来获益，所以退化成 FIFO。平均周转时间是 (200+400+600)/3 = 400。

## Q2

> Now do the same but with jobs of different lengths: 100, 200, and 300.

- Prediction / 预测:

预测命令：`scheduler.py -l 100,200,300 -p FIFO` 与 `-p SJF`。

| 作业 | 长度 | 响应 | 周转 | 等待 |
|---|---|---|---|---|
| Job 0 | 100 | 0 | 100 | 0 |
| Job 1 | 200 | 100 | 300 | 100 |
| Job 2 | 300 | 300 | 600 | 300 |
| **平均** | | **133.33** | **333.33** | **133.33** |

FIFO 与 SJF 结果相同。

- Reasoning / 理由:

作业到达顺序本来就是从短到长，所以 FIFO 的运行顺序和 SJF 选出的顺序一样。

- Verified result / 验证结果:

`data/q2_fifo.txt`、`data/q2_sjf.txt`：平均响应时间 133.33，平均周转时间 333.33，与预测一致。

- Analysis / 分析（补充实验：反序到达 300, 200, 100）:

| 调度器 | 运行顺序 | 平均响应 | 平均周转 | 输出文件 |
|---|---|---|---|---|
| FIFO | 300 → 200 → 100 | 266.67 | 466.67 | `data/q2_reverse_fifo.txt` |
| SJF | 100 → 200 → 300 | 133.33 | 333.33 | `data/q2_reverse_sjf.txt` |

到达顺序反过来后，FIFO 让长作业先跑，两个较短的作业都被“堵”在后面，平均周转时间从 333.33 升到 466.67。这就是**护航效应（convoy effect）**。SJF 不受到达顺序影响，结果仍然是 333.33。

## Q3

> Now do the same, but also with the RR scheduler and a time-slice of 1.

- Prediction / 预测:

预测命令：`scheduler.py -l 100,200,300 -p RR -q 1`。

| 作业 | 长度 | 响应 | 周转 | 等待 |
|---|---|---|---|---|
| Job 0 | 100 | 0 | 298 | 198 |
| Job 1 | 200 | 1 | 499 | 299 |
| Job 2 | 300 | 2 | 600 | 300 |
| **平均** | | **1.00** | **465.67** | **265.67** |

- Reasoning / 理由:

时间片为 1 时，三个作业在最初 3 秒内各运行一次，所以响应时间分别是 0、1、2。

- 三个作业都还在时，每一轮占 3 秒。Job 0 在第 100 轮完成第 100 秒的工作，该轮从 3×99 = 297 开始，所以 Job 0 在 298 完成。
- 到时间 300 时，三个作业都已经各运行了 100 秒。之后只剩 Job 1（还需 100）和 Job 2（还需 200）交替运行，每轮 2 秒。Job 1 在第 100 轮完成，时刻是 300 + 2×99 + 1 = 499。
- 最后 Job 2 单独运行剩下的 100 秒，在 600 完成。

- Verified result / 验证结果:

`data/q3_rr.txt`：平均响应时间 1.00，平均周转时间 465.67，与预测一致。补充实验用了 Q1 的等长负载 `-l 200,200,200 -p RR -q 1`，结果见 `data/q3_rr_equal.txt`：平均响应时间 1.00，平均周转时间 599.00。

- Analysis / 分析:

| 负载 | 调度器 | 平均响应 | 平均周转 |
|---|---|---|---|
| 100, 200, 300 | FIFO / SJF | 133.33 | 333.33 |
| 100, 200, 300 | RR (q=1) | **1.00** | 465.67 |
| 200, 200, 200 | FIFO / SJF | 200.00 | 400.00 |
| 200, 200, 200 | RR (q=1) | **1.00** | 599.00 |

RR 的响应时间最好，但周转时间最差。原因是它把每个作业都拆成很多小片轮流执行，所有作业都被拖到接近最后才完成。等长负载下这个问题最明显：三个作业分别在 598、599、600 完成，几乎同时结束。这体现了响应时间与周转时间之间的权衡：对公平、及时响应有利的策略，对周转时间不利。

## Q4

> For what types of workloads does SJF deliver the same turnaround times as FIFO?

- Prediction / 预测:

当作业的**到达顺序已经是按长度从短到长排列**（不递减）时，SJF 和 FIFO 的周转时间相同。所有作业等长是其中的特例。更一般地说，只要 FIFO 的运行顺序和 SJF 的运行顺序一致（只在等长作业之间顺序不同也算），两者的周转时间就相同。

- Reasoning / 理由:

在本模拟器里，FIFO 和 SJF 都是非抢占式调度，唯一的区别是运行顺序：FIFO 按到达顺序，SJF 按长度排序。如果到达顺序本身就是从短到长，两者执行的是同一条轨迹，各项指标自然完全相同。只要队列中有一个较长的作业排在较短作业前面，FIFO 就会让短作业等待更久，平均周转时间就会比 SJF 大。

- Verified result / 验证结果:

| 负载（到达顺序） | FIFO 平均周转 | SJF 平均周转 | 是否相同 | 输出文件 |
|---|---|---|---|---|
| 200, 200, 200（等长） | 400.00 | 400.00 | 相同 | `q1_fifo.txt` / `q1_sjf.txt` |
| 100, 200, 300（短到长） | 333.33 | 333.33 | 相同 | `q2_fifo.txt` / `q2_sjf.txt` |
| 300, 200, 100（长到短） | 466.67 | 333.33 | 不同 | `q2_reverse_fifo.txt` / `q2_reverse_sjf.txt` |
| 300, 100, 200（乱序） | 433.33 | 333.33 | 不同 | `q4_unsorted_fifo.txt` / `q4_unsorted_sjf.txt` |

- Analysis / 分析:

结果符合预测。顺序被打乱时，SJF 总能得到最小的平均周转时间（作业同时到达时，SJF 是最优的）；FIFO 偏离这个最优值的程度，取决于长作业排得有多靠前。

## Q5

> For what types of workloads and quantum lengths does SJF deliver the same response times as RR?

- Prediction / 预测:

设 RR 队列中第 k 个作业前面的作业为 i < k。

- RR 的响应时间：R_k(RR) = Σ_{i<k} min(L_i, q)
- SJF 的响应时间：R_k(SJF) = Σ_{i<k} L_i（按从短到长排序后）

两者相同的条件是：

1. RR 的队列顺序就是从短到长（作业按长度不递减的顺序到达），并且
2. 时间片 q ≥ 除最后一个作业外每个作业的长度，这样前面的作业都能在第一个时间片内跑完，min(L_i, q) = L_i。

这时 RR 的第一轮其实就是 SJF（也是 FIFO）。特例：所有作业等长 L，且 q ≥ L。

- Reasoning / 理由:

响应时间只取决于每个作业**第一次**被调度之前，前面的作业占用了多少 CPU。如果 q 小于某个前面作业的长度，RR 会提前把 CPU 切给后面的作业，后面作业的响应时间就会比 SJF 小。因此 q 较小时，RR 的响应时间严格优于 SJF；q 足够大时，两者相等。

- Verified result / 验证结果:

| 负载 | 调度器 | 各作业响应时间 | 平均响应 | 输出文件 |
|---|---|---|---|---|
| 100, 200, 300 | SJF | 0, 100, 300 | 133.33 | `q5_sjf.txt` |
| 100, 200, 300 | RR q=100 | 0, 100, 200 | 100.00（不同） | `q5_rr_q100.txt` |
| 100, 200, 300 | RR q=200 | 0, 100, 300 | 133.33（相同） | `q5_rr_q200.txt` |
| 100, 200, 300 | RR q=300 | 0, 100, 300 | 133.33（相同） | `q5_rr_q300.txt` |
| 200, 200, 200 | SJF | 0, 200, 400 | 200.00 | `q5_equal_sjf.txt` |
| 200, 200, 200 | RR q=100 | 0, 100, 200 | 100.00（不同） | `q5_equal_rr_q100.txt` |
| 200, 200, 200 | RR q=200 | 0, 200, 400 | 200.00（相同） | `q5_equal_rr_q200.txt` |

- Analysis / 分析:

对 100, 200, 300 这组负载，条件 2 要求 q ≥ max(100, 200) = 200。实验中 q=200 和 q=300 时响应时间与 SJF 相同，q=100 时不同，与推导一致。q=100 时 Job 1 只跑了 100 就被切走，Job 2 提前在 200 开始运行，所以 RR 的响应时间反而更好。

## Q6

> What happens to response time with SJF as job lengths increase? Can you use the simulator to demonstrate the trend?

- Prediction / 预测:

SJF 中，一个作业的响应时间等于排在它前面的所有较短作业的长度之和，所以**响应时间随作业长度线性增长**。N 个长度都为 L 的作业，平均响应时间 = L·(N−1)/2；当 N = 3 时，平均响应时间正好等于 L。所有作业长度同时乘以 c 倍，平均响应时间也乘以 c 倍。

- Reasoning / 理由:

SJF 是非抢占式的。一个作业开始运行后会一直跑完，后面的作业只能等待，所以前面作业越长，后面作业等得越久。

- Verified result / 验证结果:

| 负载（3 个作业） | 平均响应 | 平均周转 | 输出文件 |
|---|---|---|---|
| 100, 100, 100 | 100.00 | 200.00 | `q6_sjf_100x3.txt` |
| 200, 200, 200 | 200.00 | 400.00 | `q6_sjf_200x3.txt` |
| 300, 300, 300 | 300.00 | 600.00 | `q6_sjf_300x3.txt` |
| 400, 400, 400 | 400.00 | 800.00 | `q6_sjf_400x3.txt` |
| 500, 500, 500 | 500.00 | 1000.00 | `q6_sjf_500x3.txt` |
| 100, 200, 300 | 133.33 | 333.33 | `q2_sjf.txt` |
| 200, 400, 600（×2） | 266.67 | 666.67 | `q6_sjf_scaled_x2.txt` |
| 1000, 2000, 3000（×10） | 1333.33 | 3333.33 | `q6_sjf_scaled_x10.txt` |

- Analysis / 分析:

等长负载下，平均响应时间从 100 增到 500，与长度 L 成正比。把 100, 200, 300 放大 2 倍、10 倍后，平均响应时间也正好变为 2 倍、10 倍，趋势得到验证。这说明 SJF 只优化了周转时间，并不改善响应时间：只要作业变长，排在后面的作业（包括需要快速响应的交互式作业）都必须等待前面的作业整段跑完。要改善响应时间，需要像 RR 这样的抢占式调度。

## Q7

> What happens to response time with RR as quantum lengths increase? Can you write an equation that gives the worst-case response time, given N jobs?

- Prediction / 预测:

RR 中第 k 个作业（k = 0, 1, …, N−1）要等前面 k 个作业各用完一个时间片，所以响应时间 = k·q（假设每个作业长度都 ≥ q）。

- 平均响应时间 = q·(N−1)/2，随 q 线性增长。
- **最坏情况响应时间**（队列最后一个作业）：

  **R_worst = (N − 1) · q**

- 若有作业比 q 短，更一般的写法是 R_worst = Σ_{i=1}^{N−1} min(L_i, q) ≤ (N−1)·q。
- 当 q ≥ 所有作业长度时，RR 退化为 FIFO，响应时间不再随 q 增长。

- Reasoning / 理由:

队列中最后一个作业第一次运行之前，前面 N−1 个作业每个最多占用一个时间片 q。

- Verified result / 验证结果（3 个长度 300 的作业，`-l 300,300,300 -p RR -q Q`）:

| q | 各作业响应时间 | 平均响应 | 最坏响应 | (N−1)·q | 平均周转 | 输出文件 |
|---|---|---|---|---|---|---|
| 1 | 0, 1, 2 | 1.00 | 2 | 2 | 899.00 | `q7_rr_q1.txt` |
| 10 | 0, 10, 20 | 10.00 | 20 | 20 | 890.00 | `q7_rr_q10.txt` |
| 50 | 0, 50, 100 | 50.00 | 100 | 100 | 850.00 | `q7_rr_q50.txt` |
| 100 | 0, 100, 200 | 100.00 | 200 | 200 | 800.00 | `q7_rr_q100.txt` |
| 200 | 0, 200, 400 | 200.00 | 400 | 400 | 800.00 | `q7_rr_q200.txt` |
| 300 | 0, 300, 600 | 300.00 | 600 | 600 | 600.00 | `q7_rr_q300.txt` |
| 500 | 0, 300, 600 | 300.00 | 600 | (≤ 1000) | 600.00 | `q7_rr_q500.txt` |

公式的另外两项检验：

| 负载 | q | N | 最坏响应 | 公式 | 输出文件 |
|---|---|---|---|---|---|
| 300 × 5 | 50 | 5 | 200 | (5−1)·50 = 200 | `q7_rr_n5_q50.txt` |
| 100, 300, 300 | 200 | 3 | 300 | min(100,200) + min(300,200) = 300 ≤ 400 | `q7_rr_mixed_q200.txt` |

- Analysis / 分析:

q 从 1 增到 300 时，平均响应时间和最坏响应时间都按 q 线性增长，最坏值始终等于 (N−1)·q。q=500 已经超过作业长度 300，每个作业在第一个时间片内就能跑完，RR 变成了 FIFO，响应时间停在 300 / 600 不再变化。

同时，平均周转时间随 q 增大从 899 降到 600。这说明 q 是响应时间与周转时间之间的权衡旋钮：q 越小，响应越快，但作业被切得越碎、完成得越晚；q 越大，越接近 FIFO。此外，模拟器没有计入上下文切换开销。在真实系统中，q 太小会让切换开销占很大比例，所以实际的时间片要足够大，才能**摊销（amortize）**切换成本。

---

## 总结

| 调度器 | 平均周转时间 | 平均响应时间 | 特点 |
|---|---|---|---|
| FIFO | 取决于到达顺序，长作业在前时很差（护航效应） | 同样受到达顺序影响 | 简单，非抢占 |
| SJF | 作业同时到达时最优 | 随作业长度线性增长 | 非抢占，需要预先知道作业长度 |
| RR | 通常最差，q 越小越差 | 最好，最坏情况为 (N−1)·q | 抢占，公平，q 是权衡参数 |
